# مشارکت

## راه انداختن کد

```bash
git clone https://github.com/amirAI-dot/django-httponly-jwt.git
cd django-httponly-jwt
uv tool install nox
```

همه چیز با nox اجرا می‌شود، پس هر دستگاهی - و CI - همان کار را اجرا می‌کند. با
[uv](https://docs.astral.sh/uv/) نصب‌شده، Pythonی که نیست گرفته می‌شود.

| session | چه چیزی را نگه می‌دارد |
|---|---|
| `nox -s lint` | ruff، کد و قالب‌بندی‌اش |
| `nox -s types` | mypy، سخت‌گیرانه |
| `nox -s tests` | تست‌ها، روی همه‌ی Pythonها و Djangoهای پشتیبانی‌شده، با پوشش ۱۰۰٪ |
| `nox -s messages` | کاتالوگ فارسی همه‌ی رشته‌های علامت‌خورده را دارد، و نه بیشتر |
| `nox -s package` | wheel ساخته و نصب می‌شود، و تست‌ها و پروژه‌ی نمونه روی آن اجرا می‌شوند |
| `nox -s docs` | همین سایت ساخته می‌شود، بدون هیچ هشداری |

یک ترکیب از تست‌ها، هنگام کار:

```bash
nox -s "tests(3.13-django6.1)"
```

## قراردادها

* **کد فقط انگلیسی.** هر پیامی که کسی می‌خواند برای ترجمه علامت می‌خورد؛ فارسی در
  کاتالوگ است. رشته‌ی فارسی در تست به شکل escapeهای `\u` نوشته می‌شود.
* **هر تست به نام رفتاری است که نگه می‌دارد** - اینکه اگر شکست بخورد در دنیا چه چیزی
  خراب می‌شود، نه اینکه کدام ماژول را پوشش می‌دهد.
* **تستی که اول شکست می‌خورد.** هر رفع با تستی می‌آید که بدون آن شکست می‌خورد.
* **کوئری‌ها شمرده می‌شوند.** تمدید دو تا هزینه دارد؛ نشست معتبر هیچ. تغییری که یکی اضافه
  کند تصمیمی است که نوشته می‌شود، نه یک اتفاق.
* **docstring هر ماژول می‌گوید چرا وجود دارد.**
* **مستندات به انگلیسی و فارسی است**، و با هم عوض می‌شوند. هر صفحه و همزاد فارسی‌اش
  سرتیترها، جدول‌ها و کدهای یکسان دارند.

## تغییری در آنچه کسی می‌خواند

بعد از علامت زدن یک رشته:

```bash
nox -s messages
```

این session رشته‌ها را دوباره استخراج می‌کند و با هر تفاوتی شکست می‌خورد - فارسی آنچه
اضافه کرده را بنویسید، بعد کاتالوگ را با `django-admin compilemessages` در
`src/httponly_jwt` کامپایل کنید.
